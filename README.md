# 📡 TGLeadMonitor

Юзербот-парсер Telegram-чатов + бот управления. Слушает выбранные группы и каналы от вашего аккаунта,
ищет сообщения по ключевым словам и присылает карточки лидов в личку бота. Всё настраивается кнопками прямо в Telegram.

* **Юзербот** (Telethon) — читает чаты, вступает в новые по очереди с задержкой, выходит из чатов по вашей команде, фильтрует сообщения.
* **Бот управления** (aiogram 3) — меню, настройки, статистика, экспорт, карточки лидов.
* **SQLite** (aiosqlite) — чаты, категории и ключи, стоп-слова, лиды, настройки.

## Возможности

* Навигация без спама: переходы по меню редактируют одно и то же сообщение (новые сообщения бот отправляет только для первого `/start`, файлов экспорта/бэкапа и карточек лидов).
  Кнопка «Назад» возвращает ровно на уровень вверх (с номером страницы) и сбрасывает FSM.
* Добавление чатов: `@username`, `https://t.me/...`, приглашения `t.me/+...`, список ссылок или `.txt`-файл (до 1 МБ). За один ввод обрабатывается не более 500 ссылок, дубликаты отсеиваются.
* Вступление в чаты: фоновая очередь с задержкой 10/20/45/60 сек., обработка `FloodWaitError`, статусы `🟢 ⏸ ⏳ ❌`.
* Импорт групп и каналов, в которых аккаунт уже состоит.
* Категории ключей, режимы поиска «по вхождению» и «точное слово», стартовый пресет при первом запуске.
* **Мульти-триггеры:** одно сообщение проверяется по **всем** категориям; карточка объединяет все сработавшие категории и все уникальные совпавшие слова.
* Стоп-слова, чёрный список авторов, фильтр длины, игнор ботов и каналов.
* Антидубли по SHA-256 хешу текста (выкл / 6 / 24 / 72 ч).
* Карточки лидов с подсветкой каждого совпавшего ключа, ссылкой на сообщение, кнопками «Написать автору», «ЧС автора» и «Скрыть».
* Статистика (сегодня / 7 дней / всё время, топ-5 чатов и ключей), экспорт в CSV (UTF-8-SIG, для Excel) и TXT.
* Бэкап и восстановление настроек в JSON.
* Доступ только для `ADMIN_ID` — остальные пользователи игнорируются.

## Что понадобится

1. **Python 3.11+**.
2. **Токен бота** — создайте бота у [@BotFather](https://t.me/BotFather).
3. **Ваш числовой Telegram ID** — например, у [@userinfobot](https://t.me/userinfobot).
4. **API ID и API Hash** — на https://my.telegram.org → *API development tools*.
5. Отдельный Telegram-аккаунт для юзербота (рекомендуется — см. раздел «Безопасность»).

Зависимости (`requirements.txt`): `aiogram`, `telethon`, `aiosqlite`, `python-dotenv`, `qrcode` (нужен только для отрисовки QR-кода в консоли при входе по QR).

## Установка и запуск

**Windows:** двойной клик по `start.bat`.
**Linux / macOS:** `./start.sh` (при необходимости `chmod +x start.sh`).

Скрипты сами создают `.venv`, ставят зависимости из `requirements.txt` и запускают `main.py`.

Вручную:

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

### Первый запуск

1. Если файла `.env` нет или он заполнен не полностью, консольный мастер спросит `BOT_TOKEN`, `ADMIN_ID`, `API_ID`, `API_HASH` и сохранит их в `.env`.
   Можно и вручную: скопируйте `.env.example` в `.env` и заполните.
2. Если в `data/userbot.session` нет авторизованной сессии, программа предложит выбрать способ входа юзербота
   (если сессия уже авторизована, меню не показывается):

   ```
   [1] Вход по QR-коду
   [2] Вход по номеру телефона
   ```

   **[1] QR-код.** QR рисуется в консоли пакетом `qrcode`. Отсканируйте его в Telegram на телефоне:
   *Настройки → Устройства → Подключить устройство*. Каждый QR ждёт сканирования 30 секунд; по истечении времени
   программа сама перевыпускает код (`qr_login.recreate()`) — всего до 10 кодов (около 5 минут), после чего возвращает в меню выбора.
   Если на аккаунте включена двухфакторная защита, будет запрошен облачный пароль (ввод скрыт, 3 попытки).
   Если QR не удалось нарисовать (нет пакета `qrcode` или консоль не поддерживает UTF-8), программа выведет ссылку для входа.

   **[2] Номер телефона.** Введите номер в международном формате (например, `+380501234567`), затем код из Telegram
   (до 3 попыток; если код устарел, запрашивается новый). При включённой двухфакторной защите будет запрошен облачный пароль
   (ввод скрыт, 3 попытки). Ошибки Telegram (неверный номер, заблокированный номер, `FloodWait` с указанием, сколько ждать,
   неверные `API_ID`/`API_HASH`) выводятся в консоль, после чего можно повторить попытку.

   После успешного входа сессия сохраняется в `data/userbot.session`, повторно авторизоваться не нужно.
3. Откройте своего бота и отправьте `/start`.

Остановка — `Ctrl+C`.

**Параметры клиента Telethon.** Клиент создаётся как `TelegramClient(сессия, API_ID, API_HASH)` без дополнительных аргументов:
модель устройства, версия системы, версия приложения и языковые параметры определяет сама библиотека Telethon — проект их не подменяет.

## Как пользоваться

| Экран | Что делает |
|---|---|
| **Главное меню** | Статус, аккаунт, счётчики, старт/пауза мониторинга без перезапуска |
| **Чаты и каналы** | Список (по 6 на странице), карточка чата, пауза, удаление, выход из чата, добавление, импорт из аккаунта |
| **Ключевые слова** | Категории и фразы, режим поиска, быстрое удаление слов |
| **Стоп-слова и фильтры** | Стоп-слова, чёрный список авторов, антидубли, длина текста, игнор ботов и каналов |
| **Статистика и экспорт** | Счётчики, топ-5, выгрузка CSV/TXT, очистка истории |
| **Настройки парсера** | Задержка вступления, звук, бэкап и восстановление JSON |

### Правила отбора сообщения

Проверки выполняются по порядку; при первом «нет» сообщение отбрасывается:

1. мониторинг включён, сообщение из группы/канала, чат в статусе `🟢`;
2. в сообщении есть текст, его длина в заданном диапазоне;
3. если включён фильтр «Игнор ботов и каналов» — сообщение не от бота и не от канала (см. ниже);
4. автор не в чёрном списке;
5. в тексте нет стоп-слов (ищутся как подстроки, без учёта регистра);
6. найден хотя бы один ключ в любой из категорий;
7. такой текст не встречался за выбранный период антидублей.

### Режимы поиска

* **По вхождению** — ключ `парсер` найдёт «парсеры», «парсера», «парсеров».
* **Точное слово** — ключ найдётся только как отдельное слово (по границам слова).

Регистр не учитывается. Режим задаётся отдельно для каждой категории.

### Мульти-триггеры

Сообщение проверяется по каждой категории, перебор не останавливается на первой сработавшей. В карточке:

* строка «Категория» — названия всех сработавших категорий через запятую (например, `Заказы, Парсинг`);
* строка «Ключ» — уникальные совпавшие слова всех сработавших категорий; если одно и то же слово есть в нескольких категориях, оно показывается один раз
  (для подсветки используется шаблон из первой категории, где оно встретилось);
* в тексте подсвечивается каждое совпавшее слово (`<b><u>…</u></b>`).

В БД, CSV и TXT лид сохраняется с теми же значениями: категории через запятую в поле категории, слова — в поле ключа.
В топ-5 ключевых слов каждое совпавшее слово учитывается отдельно.

### Фильтр «Игнор ботов и каналов»

При включённом фильтре (по умолчанию включён) отбрасываются сообщения:

* отправленные через инлайн-ботов (`via_bot_id`);
* пересланные из каналов: у пересылки есть `channel_post`, либо `from_id` или `saved_from_peer` указывают на канал/супергруппу (`PeerChannel`);
* являющиеся постами канала (`post`) или отправленные от имени канала (отправитель — `Channel`);
* отправленные ботами (`sender.bot`).

Следствие: пока фильтр включён, **собственные посты отслеживаемых каналов тоже игнорируются** — лиды приходят из групп и из комментариев
пользователей. Если нужно ловить лиды в самих каналах, выключите фильтр кнопкой «🤖 Игнор ботов и каналов» на экране «Стоп-слова и фильтры».
Пересланные сообщения от обычных пользователей фильтром не отсекаются.

### Кнопка «🚪 Выйти из чата и удалить»

Кнопка запрашивает подтверждение. После подтверждения:

* **канал или супергруппа** — аккаунт выходит через `LeaveChannelRequest`;
* **обычная (небольшая) группа** — выход через `DeleteChatUserRequest` без параметра `revoke_history`
  (метод `LeaveChannelRequest` для таких групп не применим);
* бот **не вызывает** удаление или очистку диалога и не стирает переписку — выполняется только выход из чата;
* если аккаунт уже не состоял в чате, он просто остаётся вне его, а запись удаляется (бот сообщит об этом);
* запись о чате удаляется из TGLeadMonitor; ранее найденные лиды остаются в статистике и экспорте;
* если выйти не получилось, запись не удаляется, а в карточке чата показывается ошибка.

Кнопка «🗑 Удалить из базы» только убирает чат из мониторинга — аккаунт остаётся в чате.

### Бэкап и восстановление из JSON

«💾 Бэкап настроек» присылает `backup_config.json` с чатами, категориями и ключами, стоп-словами, чёрным списком и настройками
(задержка, звук, антидубли, длина текста, фильтр ботов). Лиды в бэкап не входят.

«📥 Восстановить из JSON» **добавляет** данные к текущим, ничего не удаляя. Чаты обрабатываются так:

* **с публичной ссылкой** (`@username` или приглашение `+...`) — добавляются со статусом `⏳` и ставятся в очередь вступления
  (аккаунт будет пытаться в них вступить с заданной задержкой);
* **без публичной ссылки** (ключ вида `id:...`) — вступить автоматически нельзя, поэтому они **не включаются вслепую**:
  добавляются на паузу `⏸`, затем сразу проверяется список диалогов аккаунта.
  Если аккаунт состоит в чате — статус становится `🟢`; если нет (или чат недоступен) — `❌` с пояснением.
  Если проверку выполнить не удалось (например, ошибка Telegram), чаты остаются на паузе `⏸`.
  В карточке такого чата кнопка называется «🔍 Проверить доступ» — она повторяет проверку; после того как вы вступите в чат вручную,
  проверку можно запустить заново или нажать «🔄 Импорт из аккаунта» (он тоже переводит такие чаты в `🟢`).

## Особенности

* CSV использует разделитель `;` и кодировку UTF-8-SIG — русский Excel открывает такой файл без «кракозябр».
  Ячейки, начинающиеся с `= + - @`, экранируются (защита от CSV-инъекций).
* Если вступление упёрлось в `FloodWait`, очередь ждёт нужное время и продолжает сама; бот пришлёт служебное сообщение.
* Для чатов с заявкой на вступление статус будет `❌`; после одобрения нажмите «Повторить вступление» в карточке чата.
* Кнопка «Скрыть» не сработает для сообщений старше 48 часов (ограничение Telegram).
* Кнопка `✉️ Написать автору` у авторов без username использует ссылку `tg://user?id=...`; из-за приватности она может не открыться.

## Структура проекта

```
main.py              точка входа: мастер .env, вход юзербота (QR / телефон), asyncio.gather()
config.py            загрузка .env
database/db.py       SQLite: схема, CRUD, стартовый пресет, бэкап
userbot/monitor.py   Telethon: прослушка, фильтры, очередь вступления, выход, проверка чатов, отправка лидов
bot/keyboards.py     inline-клавиатуры (callback_data <= 64 байт)
bot/handlers.py      экраны, FSM, кнопки под лидами
utils/exporter.py    CSV / TXT / JSON
start.bat, start.sh  запуск с автосозданием .venv
```

Данные хранятся в `data/` (база `tgleadmonitor.db` и сессия `userbot.session`). Эта папка и `.env` исключены из git — **никому не передавайте** файл сессии:
он даёт полный доступ к аккаунту юзербота.

## Безопасность и ответственность

* Используйте отдельный аккаунт: автоматизация пользовательских аккаунтов может нарушать правила Telegram и приводить к ограничениям.
* Не ставьте задержку вступления ниже рекомендованной и не добавляйте сотни чатов за раз — так легче получить `FloodWait` или блокировку.
* Проект не отправляет сообщений в чужие чаты: юзербот читает сообщения, вступает в чаты и выходит из них только по вашим командам в боте.
* Собирайте и храните персональные данные (имена, ID, тексты) в соответствии с законодательством вашей страны и правилами Telegram.

## Решение проблем

| Симптом | Что делать |
|---|---|
| Бот молчит | Отправьте `/start`; проверьте, что `ADMIN_ID` — ваш ID, а не ID бота |
| Лиды не приходят | Мониторинг не на паузе? Чат со статусом 🟢? Длина текста в диапазоне? Нет ли подходящего стоп-слова или дубля? Не отсекает ли сообщение фильтр ботов и каналов (особенно если вы слушаете сами каналы)? |
| Чат со статусом ❌ | Откройте карточку чата — там текст последней ошибки |
| QR-код выглядит «кривым» или не рисуется | Включите UTF-8 в консоли (в `start.bat` это уже сделано), увеличьте окно/уменьшите шрифт или выберите вход по номеру телефона |
| Нужно заново авторизоваться | Удалите `data/userbot.session` и запустите снова |
| Нужно заново ввести ключи Telegram | Удалите `.env` и запустите снова |
